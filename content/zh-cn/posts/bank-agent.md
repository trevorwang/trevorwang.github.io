## 先看几个数字

**6500 万** —— 浙商银行一笔 Agent 基础软硬件项目的中标报价。加上此前落地的财富、供应链 Agent 项目，浙商银行在 Agent 上的公开采购金额**合计超过 7400 万元**。

**108 条** —— 浦发银行上半年上线的 **AI 流水线**数量。同期还落地了 **220 个**工程化的 Agent，数字劳动力承担的工作量超过 **2500 人年**。

**406 个 / +110%** —— 今年上半年金融行业大模型中标项目数，同比翻倍还多。其中**银行在项目数量和金额上的占比，都接近一半**。

这几个数字放在一起，说明一件事：

> **银行 Agent 的落地方式，正在从单点试验转向更系统的工程化建设。**

而更值得琢磨的，是这些钱**具体花在哪**。

## 钱不花在"应用"上了，花在"底座"上

过去聊企业上 AI，通常的思路是"买一个场景解决方案"——做个客服 Agent、做个文档识别 Agent，验收完事。

但看这三家银行最近的采购，你会发现方向变了：

- **浙商银行**（6500 万那笔）：覆盖**算力、知识工程、模型和 Agent 运行环节**——不是买应用，是买"支撑后续 Agent 开发和运行的基础环境"
- **浦发银行**：采购 **Agent 创设平台**，落点在"Agent 的批量创建和管理"
- **恒丰银行**：单独建设 **Agent 观测能力**——把投入延伸到**上线之后的运行监测**

三笔钱分别落在**生产体系的不同环节**：一个是底层运行环境，一个是批量生产线，一个是质量监控。

报道里有句话总结得很准：

> 银行的投入对象正在由具体应用，继续向开发和运行基础设施延伸。

行业里的说法更直白——**有金融科技公司直接把 Agent 平台定义为"超级工厂"**，目标是把开发、部署、评测和管理塞进同一套体系。

**为什么会有这个转变？**

因为一旦 Agent 从"几个试点"变成"几百个在跑"，原来那种一个项目一套流程的做法就崩了。开发、评测、运行管理必须标准化——**否则你根本不知道手里这一堆 Agent 谁在干什么、值不值得继续花钱。**

## 真正难的地方：流程得重新拆一遍

这是这篇报道里我觉得最有价值的部分，也是很多"Agent 落地"文章会绕过去的。

**不是所有场景都适合直接交给 Agent。**

一位股份行数据架构师给了个很清楚的分界：

> 意图识别、合同要素抽取等"非标准输入、标准输出"的任务容易落地，但信贷审批、理财规划等复杂流程，需要把模型嵌入既有工作流，由规则、权限和人工节点共同控制。

注意这个分类的逻辑——**越标准化、越容易定义对错的任务，越适合机器。**

信贷是个典型例子。今年以来苏州银行推进了文档识别、尽调、AI 审批、放款审核、贷后管理一整条线；上海银行也在对公授信的营销、尽调和贷后布局。

这些项目分布在一笔授信的不同阶段，价值密度完全不同：

> 材料读取、数据提取、财务分析等任务相对标准，更容易交给机器，越往风险判断和审批环节走，对业务经验的依赖越高。

**问题就在最后那句**：一组财务指标是否异常、哪些问题要继续追问、同样的指标放在不同产业周期中意味着什么——**这些往往没有固定答案，很多判断沉淀在资深信贷人员几十年的经验里。**

这种"只可意会"的经验，原来是没法交给系统的。

现在有些公司在试着拆——神州信息的 CreditMind 方案会把历史尽调报告、审批意见、贷款后续表现重新组织，**从中提取资深信贷人员判断风险时使用的逻辑和经验**，再用于新任务。

最终的形态是这样的：

> 标准化信息处理给机器、可提炼经验转成 Skill、关键风险判断留给人。

**"转成 Skill"** 这四个字，做 AI 应用的人应该会有共鸣。

不是把所有判断都塞给模型，而是把其中**相对明确、可以复述的那部分经验**沉淀成可调用的技能；剩下真正依赖具体客户和长期经验的判断，老老实实留给人。

这套分工说起来简单，做起来极难——**它要求业务专家深度参与知识沉淀，而不是科技部门关起门来搞。**

报道里那位数据架构师说得很实在：业务规则、SOP 和经验判断要转化成模型能识别执行的逻辑，**双方协作已经从"需求交付"延伸到"共同开发和持续调整"。**

翻译一下：业务专家不再是提需求的甲方，而是**一起做产品的人**。

## 什么叫"进入生产"？浦发给了三个标准

浦发银行首席人工智能科学家郑波，把金融 AI 进入生产概括成三条：

> 进入核心业务流程，承担过去由人完成的关键任务，并改善客户体验、经营效率或风险管理。

这三条挺硬的。对照着看，很多号称"落地"的项目其实一条都不占——**不进核心流程、只在边缘打杂、也没改善任何指标。**

尤其第一条"进入核心业务流程"，是真正的分水岭。**边缘场景的 Agent 是玩具，核心流程里的 Agent 才是资产。**

而"跨界"这件事，报道里还有个更具体的观察：

> "AI 流水线"比单个 Agent 数量更能反映流程层面的变化：不同 AI 能力按照业务顺序被重新组织，机器连续承担其中一部分任务，再在需要判断、授权和承担责任的节点交回人工。

**"再在需要判断、授权和承担责任的节点交回人工"** —— 这句话值得抄下来。

它描述了 AI 落地的真实形态：**不是 AI 全权接管，而是人和机器按节点分工的一根流水线。** 机器负责连续的、可标准化的部分；人负责那几处需要判断、需要签字、需要担责任的地方。

## 上线之后，麻烦才刚开始

很多团队以为"验收通过"就是终点，报道里点出了更真实的情况：

> Agent 上线时通过测试，并不代表后续效果会保持不变。业务规则、知识内容、客户表达都在变化，实际使用中还会不断出现新的反面案例。

**Agent 是有"保质期"的。** 模型没变，但业务环境在变，所以效果会漂移。

而且出问题时归因特别难——**你得判断问题出在哪**：

- 是知识缺失（资料没喂够）？
- 是流程设计（编排逻辑有洞）？
- 还是模型能力不够？

这三种原因的处理方式完全不同。传统软件的运维只管"系统有没有挂"，Agent 的管理要管**"效果还对不对、值不值得继续投、出异常了流程能不能被接住"**。

这也是为什么恒丰银行要**单独采购 Agent 观测能力**——这不是锦上添花，是刚需。

## 一个信号：招聘岗位变了

报道里还有个不太起眼但我觉得很重要的细节。

随着 Agent 数量增加，银行的招聘需求出现了新岗位：

- **宁波银行**：Agent 工作流构建、技术框架研发
- **平安银行**：**AI Agent 评测工程师**——职责涉及工具调用、多步推理，以及**安全和性能评测**

注意第二个岗位。**"Agent 评测工程师"** 这种事，两年前根本不存在。

它说明什么？说明 Agent 已经不是"研究项目"，而是**需要专门的质量岗位来管的生产系统**。

对工程师来说，这可能比任何行业报告都更能说明——**这个方向是真在招人、真在花预算的。**

还有个更实际的读法：**银行愿意为"评测"和"观测"单独付钱，说明这两个环节的人才现在很缺。** 会调 API、会写 Agent 的人不少；能设计 Agent 评测体系、能在效果漂移时定位原因的人，很少。这个空档，就是机会。

## 我的几点看法

看完这份材料，有几个判断想跟你分享。

**第一，Agent 落地真正的门槛，是流程拆分能力，不是模型能力。**

报道里那些数字（6500 万、108 条流水线）说明银行不缺算力和模型。真正卡住他们的是那个问题：**哪些任务能交给机器、哪些经验能沉淀成 Skill、哪些判断必须留给人。**

这个划分能力，是行业知识 + 工程能力的结合，**买不来，只能一家一家业务啃出来。**

**第二，"AI 流水线"这个提法值得记住。**

它比"Agent 数量"更接近本质——企业要的不是一堆各自为战的智能体，而是**一条能把机器任务和人工节点串起来的产线**。

这也解释了为什么钱会流向"创设平台"和"观测能力"：**流水线需要厂房和质检。**

**第三，做 AI 应用的开发者，别只盯着"能力"。**

这份报道里所有难点，几乎都不是"模型不够聪明"，而是知识怎么沉淀、流程怎么拆、效果怎么持续评估。

**如果我们在做 AI 产品时也只想着接更强的模型，很可能会在真正的工程问题上卡住。**
